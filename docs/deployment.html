1. Database Setup

1

Create the database

createdb suiloyalty
2

Apply the schema

psql suiloyalty < database/schema.sql

This creates: users, brands, qr_tokens, loyalty_avatars, loyalty_brand_nodes, point_transactions.

3

Apply migration (Sprint 3 schema update)

psql suiloyalty < backend/migrations/002_loyalty_avatar_schema.sql
4

Seed brand data (optional)

psql suiloyalty -c "
INSERT INTO brands (name, category, color) VALUES

  ('Reebok',  'Sportswear', '#10b981')
ON CONFLICT DO NOTHING;"

2. Deploy Smart Contracts

Network

Contracts are deployed to Sui devnet. Devnet resets periodically — redeploy when the RPC returns "Package not found".

1

Configure Sui CLI for devnet

sui client switch --env devnet
sui client active-address   # confirm your deployer address
sui client faucet           # fund the account
2

Build and deploy

cd contracts
sui move build
sui client publish --gas-budget 200000000

Copy the PackageID, AdminCap ID, and TreasuryCap ID from the output.

3

Update backend .env

SUI_PACKAGE_ID=0x<new-package-id>
ADMIN_CAP_ID=0x<new-admin-cap-id>
TREASURY_CAP_ID=0x<new-treasury-cap-id>

3. Backend API

1

Install dependencies

cd backend && npm install
2

Create backend/.env

See the Environment Variables section below.

3

Start the server

npm run dev   # development (tsx watch)
npm start     # production

API is available at http://localhost:3000.

Warning

ZKLOGIN_SALT_SECRET derives each user's deterministic Sui address. If you change it after users have been created, all existing wallet addresses will become unreachable and users will lose access to their NFTs.

Google OAuth Setup

1

Create OAuth credentials

Go to Google Cloud Console → APIs & Services → Credentials → Create Credentials → OAuth 2.0 Client ID. Application type: Web application.

2

Add authorised redirect URIs

http://localhost:3000/api/auth/callback   # development
Critical

The redirect URI must be hardcoded in REDIRECT_URI and match exactly what is registered in Google Cloud. Never build it dynamically from request headers.

3

Copy credentials to .env

GOOGLE_CLIENT_ID=<your-client-id>.apps.googleusercontent.com
GOOGLE_CLIENT_SECRET=GOCSPX-<your-secret>

Running Locally (All Services)

Open three terminal tabs:

# Tab 1 — Backend API (port 3000)
cd backend && npm run dev

# Tab 2 — Frontend (port 3001)
cd frontend && npm run dev

# Tab 3 — (optional) Watch contract tests
cd contracts && sui move test
Tip

The frontend proxies API calls to localhost:3000 via Next.js rewrites. Both services must be running for the zkLogin flow to work end-to-end.

Secrets Policy

SuiLoyalty handles three classes of value that must never end up in version control: Sui private keys (deployer / sponsor wallets), Google OAuth client secrets, and the HMAC secrets used for zkLogin salt derivation, QR signing, and session signing. The repository is structured so a single rule covers all of them.

Hard rule

No real secret is ever committed to this repository. backend/.env and frontend/.env.local are local-only and gitignored at three levels (root .gitignore, package .gitignore, and a final defence-in-depth check before each push).

Where each value lives

ValueLives inVisible in committed files?
SUI_PRIVATE_KEYbackend/.env (local) · GitHub Secret in CINever. CI uses a dummy placeholder because blockchain.service is mocked in every test.
GOOGLE_CLIENT_SECRETbackend/.env onlyNever. Frontend bundles must never see this value — only NEXT_PUBLIC_GOOGLE_CLIENT_ID belongs in frontend/.env.local.
ZKLOGIN_SALT_SECRET, QR_HMAC_SECRET, SESSION_SECRETbackend/.env (local) · GitHub Secret in CINever in production form. CI uses clearly-labelled ci-test-* placeholders.
Google client ID, package ID, network name.env + CI inlineYes — these are public identifiers, safe to commit.

Onboarding a new contributor

  1. Clone the repo.
  2. cp backend/.env.example backend/.env and fill in real values from a secure channel (1Password, signal, in-person).
  3. cp frontend/.env.local.example frontend/.env.local and fill in NEXT_PUBLIC_* values only.
  4. Verify nothing sensitive will be staged: git status should never show .env.

If a secret is leaked

  1. Rotate first, audit second. Generate a new Sui keypair (sui client new-address ed25519), transfer AdminCap / TreasuryCap / TokenAdminCap to the new address, then update backend/.env and the GitHub Secret.
  2. For Google credentials: revoke and reissue in the Google Cloud Console; update the GitHub Secret.
  3. For HMAC secrets: regenerate as long random strings; rotating ZKLOGIN_SALT_SECRET changes every customer's derived Sui address, so this rotation is reserved for genuine compromise.
  4. Scrub the leaked value from git history with git filter-repo if it ever made it into a commit, then force-push and notify any forks.
CI hardening

Anything sensitive in .github/workflows/*.yml must come from ${{ secrets.* }}, not a hardcoded value. The workflows currently require only GOOGLE_CLIENT_ID; add others as production deployment is wired up.

Troubleshooting

redirect_uri_mismatch

Google OAuth error 400. Ensure REDIRECT_URI in backend/.env exactly matches a URI registered in Google Cloud Console. Do not build the URI dynamically.

Package not found on devnet

Devnet resets periodically. Redeploy contracts (Step 2) and update SUI_PACKAGE_ID, ADMIN_CAP_ID, and TREASURY_CAP_ID in backend/.env.

Cannot connect to backend

Ensure the backend is running on port 3000 before starting the frontend. Check NEXT_PUBLIC_API_URL matches the backend port.

DB connection refused

Ensure PostgreSQL is running: pg_ctl status or brew services list | grep postgresql. Verify DATABASE_URL matches your local setup.
