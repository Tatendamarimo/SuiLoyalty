System Overview

SuiLoyalty is a four-layer system: a Sui Move contract layer managing on-chain NFT state, a Node.js API that bridges Google OAuth / zkLogin with blockchain transactions, a Next.js PWA for consumers, and a PostgreSQL database that mirrors on-chain state for fast queries.

Smart Contract Architecture

Two Move modules are deployed as a single package on Sui devnet. The loyalty_nft module manages the avatar NFT lifecycle; loyalty_token manages fungible token distribution.

Avatar Level Progression

Avatar level is computed as 1 + (experience / 1000). Every 1000 XP gained across all brands increases the avatar level by 1.

QR Scan Data Flow

When a consumer scans a QR code, the following state changes occur in order:

  1. DB: qr_tokens.used atomically set to TRUE (double-spend prevention)
  2. DB: Check loyalty_avatars for existing avatar
  3. Chain: loyalty_nft::mint_avatar — if no avatar exists
  4. Chain: loyalty_nft::add_brand — if brand relationship is new
  5. Chain: loyalty_nft::add_brand_points + gain_experience
  6. DB: Insert/update loyalty_brand_nodes to mirror on-chain state

Security Model

ThreatMitigation
QR replay attackAtomic UPDATE … WHERE used = FALSE — second scan returns 0 rows and is rejected
QR forgery / injectionUUID format validation regex before any DB query
OAuth redirect mismatchREDIRECT_URI hardcoded in env, never built from request headers
JWT tamperingzkLogin address derived deterministically from Google sub + HMAC salt — JWT cannot be forged to claim a different address
Unauthorised contract callsAdminCap and DistributorCap objects required for all mutations — capability pattern enforced by Move type system
Wallet address spoofingjwtToAddress derives the address from the verified JWT; the user cannot choose their Sui address
