zkLogin Google Sign-In Auth

The consumer clicks "Sign in with Google". The backend generates a fresh ephemeral keypair and nonce, redirects to Google OAuth, then exchanges the returned auth code for a JWT. The JWT is used to derive a deterministic Sui wallet address via zkLogin, which is upserted into the database. No private key is ever stored for the user.

QR Scan — First Time User On-Chain

A consumer scans a brand QR code for the first time. Because they have no LoyaltyAvatar yet, the backend mints one on-chain, adds the brand as a BrandNode, then awards points. On-chain state and off-chain DB are updated in sync.

sequenceDiagram autonumber actor User participant PWA as Next.js PWA participant API as Backend API participant QRS as qr.service participant BC as blockchain.service participant DB as PostgreSQL participant SUI as Sui Devnet User->>PWA: Scan QR code PWA->>API: POST /api/qr/validate { token_uuid, user_id } API->>API: Validate UUID format (regex guard) API->>QRS: validateQRToken(token_uuid, user_id) Note over QRS,DB: Atomic double-spend prevention QRS->>DB: BEGIN QRS->>DB: UPDATE qr_tokens SET used=TRUE WHERE token_uuid=$1 AND used=FALSE DB-->>QRS: token row (1 row = valid, 0 rows = already used) QRS->>DB: COMMIT QRS->>DB: SELECT brand name from brands QRS->>DB: SELECT loyalty_avatars WHERE user_id=$1 DB-->>QRS: (empty — no avatar) Note over QRS,SUI: First-time user — mint avatar on-chain QRS->>BC: mintAvatarOnChain(displayName, walletAddress) BC->>SUI: PTB: loyalty_nft::mint_avatar(name) SUI-->>BC: avatarObjectId BC-->>QRS: avatarObjectId QRS->>DB: INSERT loyalty_avatars (on_chain_avatar_id, user_id) QRS->>BC: addBrandToAvatarOnChain(avatarObjectId, brandName) BC->>SUI: PTB: loyalty_nft::add_brand(AdminCap, avatar, brandName) SUI-->>BC: tx digest QRS->>DB: INSERT loyalty_brand_nodes (user_id, brand_id, brandName, points) QRS->>BC: addBrandPointsOnChain(avatarObjectId, brandName, points) BC->>SUI: PTB: loyalty_nft::add_brand_points + gain_experience SUI-->>BC: txDigest BC-->>QRS: txDigest QRS-->>API: { token, tx_digest } API-->>PWA: { success: true, token, tx_digest } PWA->>User: Show points awarded + avatar

QR Scan — Returning User On-Chain

A returning consumer scans a QR code for a brand they already have a relationship with. The backend skips minting and brand creation — it only awards additional points on-chain and updates the DB.

sequenceDiagram autonumber actor User participant PWA as Next.js PWA participant API as Backend API participant QRS as qr.service participant BC as blockchain.service participant DB as PostgreSQL participant SUI as Sui Devnet User->>PWA: Scan QR code PWA->>API: POST /api/qr/validate { token_uuid, user_id } API->>QRS: validateQRToken(token_uuid, user_id) QRS->>DB: BEGIN QRS->>DB: UPDATE qr_tokens SET used=TRUE WHERE used=FALSE DB-->>QRS: token row QRS->>DB: COMMIT QRS->>DB: SELECT loyalty_avatars WHERE user_id=$1 DB-->>QRS: { on_chain_avatar_id } QRS->>DB: SELECT loyalty_brand_nodes WHERE user_id=$1 AND brand_id=$2 DB-->>QRS: { id } (brand node exists) QRS->>DB: UPDATE loyalty_brand_nodes SET points_balance += $1, tier = CASE ... Note over DB: Tier auto-calculated (points / 500) QRS->>BC: addBrandPointsOnChain(avatarObjectId, brandName, points) BC->>SUI: PTB: add_brand_points + gain_experience SUI-->>BC: txDigest BC-->>QRS: txDigest QRS-->>API: { token, tx_digest } API-->>PWA: { success: true, token, tx_digest } PWA->>User: Show updated points balance

QR Replay Prevention Security

If a consumer attempts to scan the same QR code twice — or if two requests arrive simultaneously — the atomic UPDATE … WHERE used = FALSE ensures only one succeeds. The second request receives 0 rows and is rejected before any blockchain call is made.

sequenceDiagram autonumber actor Attacker participant API as Backend API participant QRS as qr.service participant DB as PostgreSQL participant SUI as Sui Devnet Note over Attacker: Attempt 1 (legitimate scan) Attacker->>API: POST /api/qr/validate { token_uuid } API->>QRS: validateQRToken(token_uuid, user_id) QRS->>DB: BEGIN QRS->>DB: UPDATE qr_tokens SET used=TRUE WHERE token_uuid=$1 AND used=FALSE DB-->>QRS: 1 row updated ✓ QRS->>DB: COMMIT QRS->>SUI: mint / add_points SUI-->>QRS: txDigest QRS-->>API: success Note over Attacker: Attempt 2 (replay attack — same token_uuid) Attacker->>API: POST /api/qr/validate { token_uuid } API->>QRS: validateQRToken(token_uuid, user_id) QRS->>DB: BEGIN QRS->>DB: UPDATE qr_tokens SET used=TRUE WHERE token_uuid=$1 AND used=FALSE DB-->>QRS: 0 rows updated — already used QRS->>DB: ROLLBACK QRS-->>API: throw "Token is invalid, already used, or expired" API-->>Attacker: 400 Bad Request Note over SUI: No blockchain call made

Merchant QR Generation Merchant

A merchant uses the merchant terminal to generate a batch of QR codes for a brand campaign. Each token is stored in the database with a UUID. The frontend renders them as printable QR codes.

sequenceDiagram autonumber actor Merchant participant Terminal as Merchant Terminal participant API as Backend API participant DB as PostgreSQL Merchant->>Terminal: Select brand + points value + quantity loop For each QR code Terminal->>API: POST /api/qr/generate { brand_id, points_value } API->>DB: INSERT qr_tokens (token_uuid=randomUUID(), brand_id, points_value) DB-->>API: { token_uuid, ... } API-->>Terminal: { success: true, token } end Terminal->>Terminal: Render QR codes from token_uuids Terminal->>API: POST /api/qr/mark-printed { token_uuids[] } API->>DB: UPDATE qr_tokens SET printed=TRUE WHERE token_uuid = ANY($1) DB-->>API: OK API-->>Terminal: { success: true } Merchant->>Terminal: Download / print QR sheet

Consumer Dashboard Load Read

When the consumer opens their dashboard, the frontend fetches their loyalty data from the backend. The NFT avatar state is read live from the Sui RPC, while brand nodes are served from the PostgreSQL cache.

DB-->>API: { on_chain_avatar_id } API->>RPC: getObject(on_chain_avatar_id) RPC-->>API: { name, level, experience, locked } API-->>PWA: { avatar } end PWA->>User: Render avatar level, XP bar, brand cards
